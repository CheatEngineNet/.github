## Two projects. More ways in.

| Build with C# | Connect through MCP |
| :--- | :--- |
| **[CheatEngine.SDK](https://github.com/CheatEngineNet/CheatEngine.SDK)** | **[CheatEngine.Mcp](https://github.com/CheatEngineNet/CheatEngine.Mcp)** |
| Write Cheat Engine plugins as ordinary C# classes. CESDK handles the entry point and Lua bindings, with compiler diagnostics to catch mistakes while you code. | Bring Cheat Engine into your AI workflow. An in-process plugin exposes tools over the Model Context Protocol using Streamable HTTP. |
| Generated plugin entry points · Typed Lua integration · Analyzers and code fixes | Memory and scans · Symbols and disassembly · Cheat tables and debugging |
| **[Get started →](https://github.com/CheatEngineNet/CheatEngine.SDK#quick-start)** · [NuGet](https://www.nuget.org/packages/CESDK) | **[Set up the plugin →](https://github.com/CheatEngineNet/CheatEngine.Mcp#quick-start)** · [Tool catalog](https://github.com/CheatEngineNet/CheatEngine.Mcp/blob/main/skills/ce-mcp/references/tool-catalog.md) |

## Less glue. More building.

Cheat Engine already has a powerful toolbox. We're making it easier to extend that toolbox with the languages and workflows you use every day.

- **Turn an idea into a plugin.** Keep your logic in C# and let CESDK generate the plumbing.
- **Bridge C# and Lua.** Expose plugin functions to Lua and call into Cheat Engine through typed bindings.
- **Put tools within reach.** Give MCP-compatible clients access to memory inspection, scanning, and debugging workflows.
